## 性能瓶颈详解

### 1. 地名识别 (LocationNER)

**当前耗时**: 50-200ms

**瓶颈原因**:
- 字典匹配需要遍历大量地名数据
- LAC分词需要加载模型
- 高德API调用存在网络延迟

**优化方案**:

| 方案 | 预期提升 | 实施难度 |
|------|----------|----------|
| 地名字典预加载到内存 | 50% | 低 |
| 使用Trie树优化匹配 | 60% | 中 |
| 缓存高频地名识别结果 | 80% | 低 |
| 异步调用高德API | 70% | 中 |

**代码示例**:

```python
# 优化前
def extract(self, text):
    for place in self.places:  # O(n)遍历
        if place in text:
            ...

# 优化后 - 使用Trie树
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False

def extract_optimized(self, text):
    # O(m) 复杂度，m为文本长度
    results = []
    for i in range(len(text)):
        node = self.root
        for j in range(i, len(text)):
            if text[j] not in node.children:
                break
            node = node.children[text[j]]
            if node.is_end:
                results.append(text[i:j+1])
    return results
```

### 2. RAG检索 (BGERetriever)

**当前耗时**: 100-500ms

**瓶颈原因**:
- BGE模型编码耗时
- 向量相似度计算耗时
- 文档加载和解析

**优化方案**:

| 方案 | 预期提升 | 实施难度 |
|------|----------|----------|
| 预计算并缓存文档向量 | 90% | 低 |
| 使用FAISS加速检索 | 95% | 中 |
| 批量编码优化 | 50% | 低 |
| 减少检索文档数量 | 30% | 低 |

**代码示例**:

```python
# 优化前
def search(self, query, top_k=5):
    query_vec = self.encode(query)  # 每次都编码
    scores = cosine_similarity(query_vec, self.doc_vecs)
    return top_k_results

# 优化后
def search_optimized(self, query, top_k=5):
    # 检查缓存
    cache_key = hash(query)
    if cache_key in self.query_cache:
        return self.query_cache[cache_key]
    
    query_vec = self.encode(query)
    
    # 使用FAISS加速
    if self.use_faiss:
        distances, indices = self.faiss_index.search(query_vec, top_k)
        results = [self.documents[i] for i in indices[0]]
    else:
        scores = cosine_similarity(query_vec, self.doc_vecs)
        results = top_k_results
    
    self.query_cache[cache_key] = results
    return results
```

### 3. 分类预测 (ClassifierRuntime)

- BERT模型推理耗时

**优化方案**:

| 方案 | 预期提升 | 实施难度 |
|------|----------|----------|
| 模型预加载和常驻内存 | 95% | 低 |
| 使用ONNX Runtime加速 | 60% | 中 |
| 模型量化 (INT8/FP16) | 50% | 中 |
| 批量预测 | 70% | 低 |

**代码示例**:

```python
# 优化前
def predict(self, tag, title, body):
    model = self.load_model()  # 每次加载
    result = model.predict(...)
    return result

# 优化后
class OptimizedClassifier:
    _instance = None
    _model = None
    
    @classmethod
    def get_instance(cls):
        if cls._instance is None:
            cls._instance = cls()
            cls._model = cls._load_model_once()
        return cls._instance
    
    def predict(self, tag, title, body):
        # 模型已预加载，直接推理
        return self._model.predict(...)
```

### 4. 回复生成 (Qwen+LoRA)

**当前耗时**: 500-2000ms (最大瓶颈)

**瓶颈原因**:
- 大模型推理本身耗时
- Token生成是串行的
- LoRA适配器加载
- GPU内存管理

**优化方案**:

| 方案 | 预期提升 | 实施难度 |
|------|----------|----------|
| 模型预加载和常驻GPU | 90% | 低 |
| 使用vLLM加速推理 | 80% | 中 |
| 减少max_new_tokens | 线性提升 | 低 |
| 使用KV Cache | 50% | 中 |
| 批量生成 | 60% | 中 |

**代码示例**:

```python
# 优化前
def generate(self, prompt):
    model = load_model()  # 每次加载
    output = model.generate(prompt, max_new_tokens=300)
    return output

# 优化后
class OptimizedGenerator:
    _model = None
    _tokenizer = None
    
    @classmethod
    def initialize(cls):
        if cls._model is None:
            cls._model = load_model_once()
            cls._tokenizer = load_tokenizer_once()
    
    def generate(self, prompt):
        # 使用KV Cache加速
        with torch.no_grad():
            inputs = self._tokenizer(prompt, return_tensors="pt").cuda()
            outputs = self._model.generate(
                **inputs,
                max_new_tokens=200,  # 减少token数
                use_cache=True,      # 启用KV Cache
                do_sample=False      # 确定性生成更快
            )
        return self._tokenizer.decode(outputs[0])
```
