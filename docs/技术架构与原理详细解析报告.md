#### 1.1.2 技术流转链路

**完整请求处理流程：**

```
用户输入 → 输入验证 → 地名识别 → RAG检索 → 分类预测 → 回复生成 → 结果返回
    ↓           ↓           ↓           ↓           ↓           ↓
  清洗数据   提取地区   检索政策   预测单位   生成回复   存储反馈
```

**详细步骤说明：**

1. **用户输入接收**：前端通过 POST `/api/analyze` 提交留言数据
2. **输入验证与清洗**：验证输入合法性，清洗恶意内容
3. **地名识别**：从留言中提取北京市行政区划信息
4. **RAG检索**：基于BGE向量检索相关政策案例
5. **分类预测**：RoBERTa模型预测回复单位
6. **回复生成**：Qwen+LoRA生成政务回复
7. **结果整合**：整合所有分析结果返回前端
8. **反馈收集**：用户评价存储到SQLite数据库

#### 2.1.2 底层原理解析

**1. 恶意模式检测原理**

采用**正则表达式匹配**技术，检测常见的Web攻击模式：

- **SQL注入检测**：`(\b(SELECT|INSERT|UPDATE|DELETE|DROP|UNION)\b)`
- **XSS攻击检测**：`(<script[^>]*>.*?</script>)`
- **命令注入检测**：`(\||;|\$\(|\`\`|&&|\|\|)`

**数学原理：**

正则表达式基于**有限状态自动机 (DFA/NFA)** 实现：

```
输入字符串 → 词法分析 → 状态转换 → 模式匹配 → 威胁判定
```

**2. 输入清洗原理**

采用**HTML实体编码**和**字符转义**：

```python
def sanitize_input(self, text: str) -> str:
    # HTML转义
    text = html.escape(text)
    # 移除危险字符
    text = re.sub(r'[<>"\']', '', text)
    # 标准化空白
    text = ' '.join(text.split())
    return text
```

**转义映射表：**

| 原字符 | 转义后 | 防护目的 |
|-------|-------|---------|
| `<` | `&lt;` | 防止HTML注入 |
| `>` | `&gt;` | 防止HTML注入 |
| `"` | `&quot;` | 防止属性注入 |
| `'` | `&#x27;` | 防止属性注入 |

#### 2.2.2 底层原理解析

**1. 地名识别算法**

采用**规则匹配 + 别名映射**的混合策略：

```
输入文本 → 分词处理 → 模式匹配 → 别名归一化 → 置信度计算 → 结果输出
```

**算法流程：**

```python
def resolve(self, text: str) -> dict:
    # Step 1: 正则模式匹配
    matches = []
    for pattern in self.PLACE_PATTERNS:
        matches.extend(re.finditer(pattern, text))
    
    # Step 2: 别名归一化
    districts = set()
    for match in matches:
        raw_name = match.group()
        normalized = self.normalize_district_name(raw_name)
        districts.add(normalized)
    
    # Step 3: 置信度计算
    if len(districts) == 1:
        confidence = 1.0
    elif len(districts) > 1:
        confidence = 0.7  # 多个地区，置信度降低
    else:
        confidence = 0.0  # 未识别
    
    return {
        "district": list(districts)[0] if districts else "未识别",
        "places": [...],
        "confidence": confidence
    }
```

**2. 别名映射原理**

**映射表结构：**

#### 2.3.2 底层原理解析

**1. BGE向量检索原理**

**BGE (BAAI General Embedding)** 是基于BERT的中文向量模型：

**模型架构：**

```
输入文本 → BERT编码器 → [CLS]向量 → 归一化 → 文档向量
```

**数学原理：**

**向量表示：**

```
v_doc = Normalize(BERT(text))
```

其中：
- `BERT(text)` 是BERT模型的输出向量
- `Normalize(v) = v / ||v||_2` 是L2归一化

**相似度计算：**

```
similarity(q, d) = cos(v_q, v_d) = (v_q · v_d) / (||v_q|| × ||v_d||)
```

由于向量已归一化，简化为：

```
similarity(q, d) = v_q · v_d
```

**2. 索引构建流程**

```python
def _build_index(self):
    # Step 1: 加载语料
    docs = self._load_docs(corpus_path)
    
    # Step 2: 文本组合
    corpus = [self._compose_doc_text(doc) for doc in docs]
    
    # Step 3: 向量编码
    self.doc_vectors = self.embedding_model.encode(
        corpus,
        normalize_embeddings=True,  # L2归一化
        show_progress_bar=False
    )
    
    # Step 4: 存储向量
    # doc_vectors.shape = (N, 768)  # N个文档，768维向量
```

**3. 检索流程**

```python
def retrieve(self, query: str, district: str, top_k: int):
    # Step 1: 查询向量化
    query_vector = self.embedding_model.encode(
        [query],
        normalize_embeddings=True
    )
    
    # Step 2: 计算相似度
    similarities = np.dot(self.doc_vectors, query_vector.T)
    
    # Step 3: 地区过滤
    if district:
        mask = [doc['district'] in [district, '全市'] for doc in self.docs]
        similarities = similarities * mask
    
    # Step 4: Top-K选择
    top_indices = np.argsort(similarities)[-top_k:][::-1]
    
    # Step 5: 构建结果
    results = []
    for idx in top_indices:
        results.append(RetrievalHit(
            doc_id=self.docs[idx]['id'],
            title=self.docs[idx]['title'],
            score=float(similarities[idx]),
            ...
        ))
    
    return results
```

**时间复杂度分析：**

- 向量编码：O(1) - 预计算
- 相似度计算：O(N × D) - N文档数，D向量维度
- Top-K选择：O(N log K)

**优化策略：**

1. **向量预计算**：离线构建索引
2. **批量计算**：使用矩阵运算
3. **近似检索**：FAISS加速（可选）

**2. FGSM对抗训练原理**

**FGSM (Fast Gradient Sign Method)** 是一种对抗训练技术：

**数学原理：**

```
x_adv = x + ε · sign(∇_x L(θ, x, y))
```

其中：
- `x` 是原始输入
- `ε` 是扰动幅度
- `∇_x L` 是损失函数对输入的梯度
- `sign(·)` 是符号函数

**训练过程：**

```python
# 正常训练
loss = model(input_ids, labels=labels).loss
loss.backward()
optimizer.step()

# 对抗训练
embeddings = model.get_input_embeddings()(input_ids)
embeddings.retain_grad()
loss = model(inputs_embeds=embeddings, labels=labels).loss
loss.backward()

# 计算对抗扰动
grad = embeddings.grad.data
adv_perturbation = epsilon * grad.sign()

# 对抗样本训练
adv_embeddings = embeddings + adv_perturbation
adv_loss = model(inputs_embeds=adv_embeddings, labels=labels).loss
adv_loss.backward()
optimizer.step()
```

**对抗训练效果：**

- 提升模型鲁棒性
- 防止过拟合
- 提高泛化能力

**3. 多标签分类原理**

**问题定义：**

给定输入文本 `x`，预测其所属的回复单位 `y`：

```
P(y|x) = softmax(W · h_{[CLS]} + b)
```

其中：
- `h_{[CLS]}` 是[CLS]位置的隐藏状态
- `W` 是分类权重矩阵
- `b` 是偏置向量

**损失函数：**

```
L = -∑ y_i log(P(y_i|x))
```

**4. Top-K预测原理**

```python
def predict_units(tag, title, body, top_k=3):
    # Step 1: 文本编码
    text = f"【{tag}】{title}。{body}"
    encoding = tokenizer(
        text,
        max_length=256,
        padding="max_length",
        truncation=True,
        return_tensors="pt"
    )
    
    # Step 2: 前向传播
    with torch.no_grad():
        logits = model(**encoding).logits
    
    # Step 3: 概率计算
    probs = torch.softmax(logits, dim=-1)[0]
    
    # Step 4: Top-K选择
    values, indices = torch.topk(probs, k=top_k)
    
    # Step 5: 结果构建
    results = []
    for value, index in zip(values, indices):
        results.append({
            "unit": id2label[str(index)],
            "confidence": round(value * 100, 1)
        })
    
    return results
```

#### 2.5.2 底层原理解析

**1. Qwen大语言模型架构**

**Qwen2.5-1.5B** 是阿里云开源的大语言模型：

**模型结构：**

```
输入文本 → Tokenizer → Token IDs → Embedding层 → Transformer解码器 → 输出层 → 文本生成
```

**详细架构：**

```
输入: "经核实，您反映的朝阳区垃圾清运问题"
  ↓
Tokenization: [825, 4495, 8024, 872, 5709, 4638, 3111, 722, 782, 3362, 3236, 3844, 684]
  ↓
Embedding Layer: (seq_len, 1536)  # 1536是隐藏层维度
  ↓
Transformer Decoder (28层):
  - Grouped Query Attention (GQA)
  - SwiGLU激活函数
  - RoPE位置编码
  - RMSNorm归一化
  ↓
Output Layer: Linear(1536, vocab_size)
  ↓
Softmax → 下一个token概率分布
```

**关键技术：**

**a) Grouped Query Attention (GQA)**

```
传统Multi-Head Attention:
  Q: (batch, heads, seq_len, head_dim)
  K: (batch, heads, seq_len, head_dim)
  V: (batch, heads, seq_len, head_dim)

Grouped Query Attention:
  Q: (batch, heads, seq_len, head_dim)
  K: (batch, groups, seq_len, head_dim)  # groups < heads
  V: (batch, groups, seq_len, head_dim)
  
优势: 减少KV Cache大小，提升推理速度
```

**b) SwiGLU激活函数**

```
SwiGLU(x) = Swish(xW₁) ⊙ (xW₂)

其中:
  Swish(x) = x · sigmoid(x)
  ⊙ 是逐元素乘法
  W₁, W₂ 是可学习参数

优势: 相比ReLU，性能更好
```

**c) RoPE位置编码**

```
RoPE(x, pos) = x · R(pos)

其中:
  R(pos) 是旋转矩阵，编码位置信息
  
优势: 
  - 相对位置编码
  - 长度外推能力强
```

**2. LoRA低秩适应原理**

**LoRA (Low-Rank Adaptation)** 是一种参数高效的微调方法：

**核心思想：**

```
原始权重矩阵: W ∈ R^(d×k)
微调权重更新: ΔW = BA
其中:
  B ∈ R^(d×r), A ∈ R^(r×k)
  r << min(d, k)  # 低秩约束
```

**数学原理：**

```
h = W₀x + ΔWx = W₀x + BAx

训练时:
  - W₀ 冻结（预训练权重）
  - A, B 可训练（低秩矩阵）
  
推理时:
  W = W₀ + BA  # 合并权重，无额外开销
```

**参数量对比：**

```
全量微调: d × k = 1536 × 1536 = 2,359,296 参数
LoRA微调 (r=8): d × r + r × k = 1536 × 8 + 8 × 1536 = 24,576 参数

参数量减少: 96倍
```

#### 2.6.2 底层原理解析

**1. LRU缓存淘汰策略**

**LRU (Least Recently Used)** 是一种缓存淘汰算法：

**数据结构：**

```
OrderedDict: {
    "model_1": {"model": ..., "timestamp": ..., "metadata": ...},
    "model_2": {"model": ..., "timestamp": ..., "metadata": ...},
    ...
}
```

**淘汰流程：**

```
访问模型 → 移动到队尾 → 检查容量 → 超出则删除队首
```

**时间复杂度：**

- 访问：O(1)
- 插入：O(1)
- 删除：O(1)

**2. TTL过期机制**

**TTL (Time To Live)** 是缓存过期策略：

```python
def get(self, key: str) -> Optional[Any]:
    if key not in self._cache:
        return None
    
    entry = self._cache[key]
    current_time = time.time()
    
    # 检查是否过期
    if current_time - entry['timestamp'] > self.ttl:
        del self._cache[key]
        return None
    
    # 更新访问时间（LRU）
    self._cache.move_to_end(key)
    return entry['model']
```

**过期检查：**

```
当前时间 - 创建时间 > TTL → 过期删除
```

**3. 线程安全机制**

**使用 `threading.RLock` 实现可重入锁：**

```python
class ModelCache:
    def __init__(self):
        self._lock = threading.RLock()
        self._cache = {}
    
    def set(self, key: str, model: Any):
        with self._lock:  # 自动加锁/解锁
            self._cache[key] = {
                'model': model,
                'timestamp': time.time(),
                'metadata': {}
            }
```

**锁的作用：**

```
线程A: set("model_1", ...) → 获取锁 → 写入 → 释放锁
线程B: get("model_1")      → 等待锁 → 获取锁 → 读取 → 释放锁
```


**WSGI接口定义：**

```python
def application(environ, start_response):
    """
    WSGI应用的标准接口
    
    Args:
        environ: 包含请求信息的字典
        start_response: 开始响应的回调函数
    
    Returns:
        响应体（可迭代对象）

    # 解析请求

    method = environ['REQUEST_METHOD']

    else:

        response_body = b'Not Found'
```

**2. 路由机制原理**

Flask使用**装饰器模式**实现URL到函数的映射：

```python
# 路由装饰器的内部实现（简化版）
class Flask:
    def __init__(self):
        self.url_map = {}  # 路由映射表
    
    def route(self, rule, **options):
        """路由装饰器"""
        def decorator(f):
            # 将URL规则和函数添加到映射表
            self.url_map[rule] = {
                'function': f,
                'methods': options.get('methods', ['GET'])
            }
            return f
        return decorator
    
    def dispatch_request(self, request):
        """请求分发"""
        url = request.path
        method = request.method
        
        # 查找路由
        if url in self.url_map:
            route_info = self.url_map[url]
            if method in route_info['methods']:
                return route_info['function']()
        
        return '404 Not Found', 404
```

**路由匹配算法：**

```
请求方法: POST

路由表:
{

    '/api/analyze': {'function': analyze, 'methods': ['POST']},
    '/api/health': {'function': health, 'methods': ['GET']}
}

匹配过程:
1. 查找URL → 找到 '/api/analyze'
2. 检查方法 → POST在允许列表中
3. 调用函数 → analyze()
4. 返回结果 → JSON响应
```

**3. 请求上下文原理**

Flask使用**上下文栈**管理请求状态：

```python
# 请求上下文栈
_request_ctx_stack = LocalStack()

class RequestContext:
    def __init__(self, app, environ):
        self.app = app
        self.request = Request(environ)
        self.session = None
    
    def push(self):
        """将上下文压入栈"""
        _request_ctx_stack.push(self)
    
    def pop(self):
        """将上下文弹出栈"""
        _request_ctx_stack.pop()

# 请求处理流程
def wsgi_app(environ, start_response):
    # 创建请求上下文
    ctx = RequestContext(app, environ)
    ctx.push()
    
    try:
        # 处理请求
        response = self.dispatch_request(ctx.request)
        return response(environ, start_response)
    finally:
        # 清理上下文
        ctx.pop()
```

**5. 会话管理原理**

Flask使用**签名Cookie**实现会话：

```python
# 会话配置
app.secret_key = 'your-secret-key'  # 用于签名

# 会话存储原理
class SecureSession:
    def __init__(self, secret_key):
        self.secret_key = secret_key
        self.serializer = JSONSerializer()
    
    def save(self, session_data):
        """保存会话到Cookie"""
        # 序列化数据
        serialized = self.serializer.dumps(session_data)
        
        # 签名（防止篡改）
        signature = hmac.new(
            self.secret_key.encode(),
            serialized,
            hashlib.sha256
        ).hexdigest()
        
        # 编码为Base64
        cookie_value = base64.b64encode(serialized + signature.encode()).decode()
        
        return cookie_value
    
    def load(self, cookie_value):
        """从Cookie加载会话"""
        # 解码Base64
        decoded = base64.b64decode(cookie_value)
        
        # 分离数据和签名
        serialized = decoded[:-64]
        signature = decoded[-64:].decode()
        
        # 验证签名
        expected_signature = hmac.new(
            self.secret_key.encode(),
            serialized,
            hashlib.sha256
        ).hexdigest()
        
        if signature != expected_signature:
            raise ValueError("会话签名验证失败")
        
        # 反序列化数据
        return self.serializer.loads(serialized)
```
