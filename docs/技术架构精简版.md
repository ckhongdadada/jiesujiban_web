# 接诉即办智能服务系统 - 技术架构精简解析

## 一、项目整体架构

### 1.1 系统是什么？

**接诉即办智能服务系统**是一个自动处理政务留言的AI系统，能够：
- 自动识别留言所属地区
- 自动预测回复单位
- 自动生成政务回复
- 提供相关政策案例参考

### 1.2 系统架构全景

```
┌─────────────────────────────────────────────────────────────┐
│                    用户交互层 (前端网页)                      │
│                   用户输入留言 → 查看分析结果                  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    API网关层 (Flask后端)                      │
│                   接收请求 → 调度各模块 → 返回结果             │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    业务逻辑层 (核心AI模块)                    │
│     地名识别 → RAG检索 → 分类预测 → 回复生成                  │
└─────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────┐
│                    数据持久层 (存储层)                        │
│     政策案例库 → 反馈数据库 → 模型权重 → 日志文件             │
└─────────────────────────────────────────────────────────────┘
```

### 1.3 核心处理流程

```
用户留言 → 输入验证 → 地名识别 → RAG检索 → 分类预测 → 回复生成 → 返回结果
```

**流程说明：**

| 步骤 | 做什么 | 为什么需要 |
|------|--------|-----------|
| 输入验证 | 检查数据合法性 | 防止恶意输入 |
| 地名识别 | 提取留言中的地区 | 精准定位问题区域 |
| RAG检索 | 查找相关政策案例 | 提供知识支撑 |
| 分类预测 | 预测回复单位 | 自动分派任务 |
| 回复生成 | 生成政务回复 | 自动化处理 |

## 二、核心模块原理

### 2.1 地名识别模块

**核心作用：** 从用户留言中识别出北京市的行政区划（如朝阳区、海淀区等）

#### 2.1.1 整体处理流程

```
┌─────────────────────────────────────────────────────────────┐
│                    地名识别处理流程                           │
└─────────────────────────────────────────────────────────────┘

用户留言："朝阳区望京街道垃圾清运不及时"
      ↓
【第一步：文本预处理】
清洗文本，去除特殊字符，统一格式
      ↓
【第二步：词典匹配】
├─ 直接匹配16个区名（朝阳区、海淀区等）
├─ 匹配别名词典（望京→朝阳区、中关村→海淀区）
└─ 匹配街道/乡镇名称
      ↓
【第三步：LAC分词识别】（可选）
使用百度LAC进行命名实体识别
识别出地名实体（LOC标签）
      ↓
【第四步：高德API查询】（备选）
调用高德地图API进行地理编码
获取精确的行政区划信息
      ↓
【第五步：结果整合】
综合多种方法的结果，选择置信度最高的区名
      ↓
输出结果："朝阳区"（置信度：0.95）
```

#### 2.1.2 核心技术详解

**1. 词典匹配**

```
┌─────────────────────────────────────────────────────────────┐
│                    词典匹配原理                              │
└─────────────────────────────────────────────────────────────┘

词典结构：
├─ 区名词典：16个北京区名
│   └─ 东城区、西城区、朝阳区、丰台区...
├─ 别名词典：地名→区的映射
│   ├─ "望京" → "朝阳区"
│   ├─ "中关村" → "海淀区"
│   ├─ "国贸" → "朝阳区"
│   └─ "西单" → "西城区"
└─ 街道词典：街道→区的映射
    ├─ "望京街道" → "朝阳区"
    └─ "中关村街道" → "海淀区"

匹配过程：
输入文本 → 遍历词典 → 查找匹配项 → 返回对应区名
```

**优势：**
- 速度快：直接查表，毫秒级响应
- 准确高：针对北京本地地名优化
- 可扩展：随时添加新地名

**2. LAC分词识别**

```
┌─────────────────────────────────────────────────────────────┐
│                    LAC分词原理                               │
└─────────────────────────────────────────────────────────────┘

什么是LAC？
LAC（Lexical Analysis of Chinese）是百度开源的中文分词工具，
能够进行分词、词性标注、命名实体识别。

处理流程：
输入："朝阳区望京街道垃圾清运不及时"
      ↓
分词 + 词性标注：
"朝阳区/LOC 望京街道/LOC 垃圾/n 清运/v 不/d 及时/a"
      ↓
提取地名实体（LOC标签）：
├─ "朝阳区"
└─ "望京街道"
      ↓
映射到区名：
"朝阳区" → 朝阳区
"望京街道" → 朝阳区（通过词典映射）
```

**LAC能识别的实体类型：**

| 标签 | 含义 | 示例 |
|------|------|------|
| LOC | 地名 | 朝阳区、望京街道 |
| ORG | 机构名 | 北京市人民政府 |
| PER | 人名 | 张三 |
| TIME | 时间 | 2024年3月 |

**优势：**
- 智能识别：能识别词典中没有的地名
- 上下文理解：根据语境判断词性
- 实体分类：区分地名、机构、人名等

**3. 高德API查询**

```
┌─────────────────────────────────────────────────────────────┐
│                    高德API原理                               │
└─────────────────────────────────────────────────────────────┘

什么是高德API？
高德地图提供的地理编码服务，能将地址文本转换为精确的经纬度
和行政区划信息。

调用流程：
输入："望京街道"
      ↓
构造请求URL：
https://restapi.amap.com/v3/geocode/geo?
  address=望京街道
  &key=你的API密钥
      ↓
发送HTTP请求
      ↓
解析返回的JSON：
{
  "geocodes": [{
    "province": "北京市",
    "district": "朝阳区",  ← 提取区名
    "adcode": "110105"

**高德API返回的信息：**

| 字段 | 含义 | 示例 |
|------|------|------|
| province | 省份 | 北京市 |
| city | 城市 | 北京市 |
| district | 区县 | 朝阳区 |

**优势：**

- 覆盖全：支持全国所有地址
- 实时更新：行政区划变更自动更新

**使用场景：**

### 2.2 RAG检索模块

**核心作用：** 从知识库中检索与留言相关的政策文件和处理案例

#### 2.2.1 整体处理流程

```
┌─────────────────────────────────────────────────────────────┐
│                    RAG检索处理流程                           │
└─────────────────────────────────────────────────────────────┘

用户留言："朝阳区垃圾清运不及时"
      ↓
【第一步：文本编码】

#### 2.2.2 什么是BGE模型？

**BGE**（BAAI General Embedding）是北京智源人工智能研究院开源的中文向量编码模型。

**模型信息：**

| 属性 | 说明 |
|------|------|
| 全称 | BAAI General Embedding |
| 开发者 | 北京智源人工智能研究院 |
| 模型名称 | bge-small-zh-v1.5 |
| 参数量 | 约3300万 |
| 向量维度 | 512维 |
| 语言 | 中文 |

**为什么选择BGE？**
- 中文效果好：专门针对中文优化
- 体积小：small版本仅100MB左右
- 速度快：编码速度快，适合实时检索
- 开源免费：可商用，无版权问题

#### 2.2.3 向量编码原理

**什么是向量编码？**

```
┌─────────────────────────────────────────────────────────────┐
│                    向量编码原理                              │
└─────────────────────────────────────────────────────────────┘

文本 → 向量（数字数组）

示例：
"垃圾清运问题" → [0.23, -0.45, 0.67, 0.12, ..., 0.34]
                  └────────────── 512个数字 ──────────────┘

向量特点：
├─ 相似的文本 → 向量也相似（数值接近）
├─ 不同的文本 → 向量差异大
└─ 向量可以计算相似度
```

**编码过程详解：**

```
输入文本："朝阳区垃圾清运不及时"
      ↓
【分词】
"朝阳" "区" "垃圾" "清运" "不" "及时"
      ↓
【词向量查找】
每个词转换为初始向量
      ↓
【Transformer编码】
通过多层Transformer处理
理解词与词之间的关系
      ↓
【池化操作】
将所有词向量合并为一个句子向量
      ↓
【归一化】
将向量长度标准化为1
      ↓
输出向量：[0.23, -0.45, 0.67, ..., 0.34]（512维）
```

**代码实现示例：**

```python
from sentence_transformers import SentenceTransformer

# 加载BGE模型
model = SentenceTransformer('BAAI/bge-small-zh-v1.5')

# 编码文本
text = "朝阳区垃圾清运不及时"
vector = model.encode(text)

# 输出向量
print(vector.shape)  # (512,) - 512维向量
print(vector[:5])    # [0.23, -0.45, 0.67, 0.12, -0.89]
```

#### 2.2.4 相似度计算原理

**什么是余弦相似度？**

```
┌─────────────────────────────────────────────────────────────┐
│                    余弦相似度原理                            │
└─────────────────────────────────────────────────────────────┘

公式：
cos(θ) = (A · B) / (|A| × |B|)

其中：
├─ A · B = 向量点积（对应位置相乘再相加）
├─ |A| = 向量A的长度
├─ |B| = 向量B的长度
└─ θ = 两个向量的夹角

几何意义：
├─ 相似度 = 1：两个向量方向完全相同
├─ 相似度 = 0：两个向量垂直（无关）
└─ 相似度 = -1：两个向量方向相反
```

**计算示例：**

```
向量A（留言）："垃圾清运问题" → [0.8, 0.6]
向量B（政策）："环境卫生管理" → [0.7, 0.7]

计算过程：
1. 点积：A · B = 0.8×0.7 + 0.6×0.7 = 0.56 + 0.42 = 0.98
2. 向量长度：|A| = √(0.8² + 0.6²) = 1.0
              |B| = √(0.7² + 0.7²) = 0.99
3. 余弦相似度：cos(θ) = 0.98 / (1.0 × 0.99) = 0.99

结论：相似度很高（0.99），两段文本语义相近
```

**代码实现示例：**

```python
import numpy as np

def cosine_similarity(vec_a, vec_b):
    """
    计算两个向量的余弦相似度
    
    Args:
        vec_a: 向量A
        vec_b: 向量B
    
    Returns:
        相似度（-1到1之间，越接近1越相似）
    """
    # 点积
    dot_product = np.dot(vec_a, vec_b)
    
    # 向量长度
    norm_a = np.linalg.norm(vec_a)
    norm_b = np.linalg.norm(vec_b)
    
    # 余弦相似度
    similarity = dot_product / (norm_a * norm_b)
    
    return similarity

# 示例
vec_a = np.array([0.8, 0.6])
vec_b = np.array([0.7, 0.7])
print(cosine_similarity(vec_a, vec_b))  # 输出: 0.99
```

#### 2.3.1 模型整体架构

本分类模型采用**BERT + CNN + Attention + TF-IDF融合架构**，包含四大核心组件：

                              ↓
        ┌─────────────────────┼─────────────────────┐
        ↓                     ↓                     ↓
┌───────────────┐    ┌───────────────┐    ┌───────────────┐
│ TF-IDF组件    │    │ BERT组件      │    │ CNN组件       │

│ (64维)       │    │ (768维)      │    │ (768维)      │
└───────────────┘    └───────────────┘    └───────────────┘
        ↓                     ↓                     ↓
        │              ┌───────────────┐            │
        │              │ Attention组件 │            │
        │              │ 注意力加权    │            │
        │              │ (768维)      │            │
        │              └───────────────┘            │

                              ↓
                    ┌─────────────────┐
                    │ 全连接分类层    │
                    └─────────────────┘
                              ↓
                    输出：城管委（0.85）
```

#### 2.3.2 四大核心组件详解

**1. BERT/RoBERTa语义编码组件**

```
┌─────────────────────────────────────────────────────────────┐
│                    BERT组件原理                              │
└─────────────────────────────────────────────────────────────┘

功能：深层语义特征提取，捕捉上下文依赖关系和语义关联

处理流程：
输入文本："朝阳区垃圾清运不及时"
      ↓
【Tokenizer编码】
转化为词元ID和注意力掩码
[101, 735, 1812, 1285, 3563, 679, 3189, 102]
      ↓
【BERT编码器】
通过多层Transformer处理
├─ 自注意力机制：理解词与词的关系
├─ 前馈神经网络：非线性变换
└─ 层归一化：稳定训练
      ↓
【输出】
last_hidden_state：每个token的向量表示
形状：(batch_size, seq_len, 768)
```

**BERT组件优势：**
- 深层语义理解：捕捉上下文关系
- 预训练知识：已学习大量语言知识
- 泛化能力强：适应多种文本类型

**2. CNN局部特征提取组件**

```
┌─────────────────────────────────────────────────────────────┐
│                    CNN组件原理 (TextCNN)                     │
└─────────────────────────────────────────────────────────────┘

功能：提取局部语义模式，捕捉短语级特征

处理流程：
BERT输出的token序列向量
形状：(batch_size, seq_len, 768)
      ↓
【维度转换】
permute为 (batch_size, 768, seq_len)
      ↓
【多尺度卷积】
使用3种不同大小的卷积核
├─ 卷积核大小=2：捕捉2词短语特征 → 256维
├─ 卷积核大小=3：捕捉3词短语特征 → 256维
└─ 卷积核大小=4：捕捉4词短语特征 → 256维
      ↓
【激活与池化】
每个卷积结果：ReLU激活 → MaxPool → squeeze
      ↓
【特征拼接】
concat([256, 256, 256]) → 768维
      ↓
【输出向量】
局部特征向量（768维）
```

**卷积操作示例：**

```
输入序列：[v1, v2, v3, v4, v5, v6]（每个vi是768维向量）

卷积核大小=2的滑动窗口：
├─ 窗口1：[v1, v2] → 卷积 → 特征1
├─ 窗口2：[v2, v3] → 卷积 → 特征2
├─ 窗口3：[v3, v4] → 卷积 → 特征3
├─ 窗口4：[v4, v5] → 卷积 → 特征4
└─ 窗口5：[v5, v6] → 卷积 → 特征5

最大池化：max(特征1...特征5) → 256维输出

同理对卷积核大小=3和=4进行操作
最终拼接：256 + 256 + 256 = 768维
```

**CNN组件优势：**
- 局部特征提取：捕捉短语级模式
- 多尺度感知：不同粒度的特征
- 与全局特征互补：增强模型表达能力

**3. Attention注意力加权组件**

```
┌─────────────────────────────────────────────────────────────┐
│                    Attention组件原理                         │
└─────────────────────────────────────────────────────────────┘

功能：对BERT输出的token向量进行注意力加权，突出重要信息

处理流程：
BERT输出的hidden_states
形状：(batch_size, seq_len, 768)
      ↓
【线性变换】
energy = tanh(W × hidden_states)
形状：(batch_size, seq_len, 768)
      ↓
【计算注意力分数】
scores = V × energy → squeeze
形状：(batch_size, seq_len)
      ↓
【掩码处理】
将padding位置的分数设为-1e9
      ↓
【Softmax归一化】
attn_weights = softmax(scores)
形状：(batch_size, seq_len)
      ↓
【加权求和】
context = Σ(hidden_states × attn_weights)
形状：(batch_size, 768)
      ↓
【输出向量】
注意力加权后的句子表示（768维）
```

**Attention机制示例：**

```
输入句子："朝阳区垃圾清运不及时"

注意力权重分布：
├─ "朝阳"：0.05
├─ "区"：0.02
├─ "垃圾"：0.25  ← 高权重
├─ "清运"：0.30  ← 高权重
├─ "不"：0.08
├─ "及时"：0.20  ← 较高权重
└─ [PAD]：0.00   ← 被掩码

加权后的句子表示更关注"垃圾清运"等关键词
```

**Attention组件优势：**
- 突出重点：自动关注重要词汇
- 抑制噪声：降低无意义词的影响
- 可解释性：注意力权重可视化

**4. TF-IDF关键词特征组件**

```
┌─────────────────────────────────────────────────────────────┐
│                    TF-IDF组件原理                            │
└─────────────────────────────────────────────────────────────┘

功能：捕捉文本中关键词的权重信息，弥补预训练模型对低频关键词敏感度不足

处理流程：
输入文本："朝阳区垃圾清运不及时"
      ↓
【jieba分词】
"朝阳" "区" "垃圾" "清运" "不" "及时"
      ↓
【TF-IDF向量化】
使用预训练的TfidfVectorizer
输出稀疏向量（3000维）
      ↓
【神经网络映射】
Linear(3000 → 128) → ReLU → Dropout
Linear(128 → 64) → LayerNorm → ReLU
      ↓
【输出向量】
关键词特征向量（64维）
```

**TF-IDF计算示例：**

```
文档："垃圾清运垃圾问题"

词频计算：
├─ "垃圾"：出现2次 → TF = 2/4 = 0.5
├─ "清运"：出现1次 → TF = 1/4 = 0.25
└─ "问题"：出现1次 → TF = 1/4 = 0.25

逆文档频率（假设100篇文档）：
├─ "垃圾"：出现在20篇 → IDF = log(100/20) = 1.61
├─ "清运"：出现在10篇 → IDF = log(100/10) = 2.30
└─ "问题"：出现在50篇 → IDF = log(100/50) = 0.69

TF-IDF权重：
├─ "垃圾"：0.5 × 1.61 = 0.805
├─ "清运"：0.25 × 2.30 = 0.575
└─ "问题"：0.25 × 0.69 = 0.173
```

**TF-IDF组件优势：**
- 捕捉关键词权重：突出重要词汇
- 弥补预训练模型不足：对低频词更敏感
- 计算速度快：传统方法，效率高

#### 2.3.6 训练优化策略

**1. Focal Loss损失函数**

```
┌─────────────────────────────────────────────────────────────┐
│                    Focal Loss原理                            │
└─────────────────────────────────────────────────────────────┘

功能：解决类别不平衡问题，关注难分类样本

公式：
FL = -α(1-pt)^γ × log(pt)

其中：
├─ α：类别权重（解决类别不平衡）
├─ γ：聚焦参数（通常取2.0）
├─ pt：模型对正确类别的预测概率
└─ (1-pt)^γ：难样本的权重更大

效果：
├─ 易分类样本（pt高）：loss被压缩
├─ 难分类样本（pt低）：loss保持较大
└─ 模型更关注难分类样本
```

**2. FGM对抗训练**

```
┌─────────────────────────────────────────────────────────────┐
│                    FGM对抗训练原理                           │
└─────────────────────────────────────────────────────────────┘

功能：提高模型鲁棒性，防止过拟合

处理流程：
正常前向传播 → 计算loss → 反向传播
      ↓
【对抗攻击】
在embedding上添加扰动：r = ε × grad / ||grad||
      ↓
【对抗训练】
使用扰动后的embedding再次前向传播
计算对抗loss → 反向传播
      ↓
【恢复参数】
恢复原始embedding
      ↓
更新参数

效果：
├─ 提高模型对扰动的鲁棒性
├─ 防止过拟合
└─ 提升泛化能力
```

**3. 早停机制**

```
┌─────────────────────────────────────────────────────────────┐
│                    早停机制原理                              │
└─────────────────────────────────────────────────────────────┘

功能：防止过拟合，自动停止训练

处理流程：
每个epoch结束后评估验证集准确率
      ↓
如果准确率连续patience个epoch没有提升
      ↓
停止训练，保存最佳模型

参数：
├─ patience：容忍轮数（默认4）
└─ min_delta：最小提升阈值（默认0.001）
```

#### 2.4.1 什么是Qwen大模型？

Qwen（通义千问）是阿里开源的大语言模型，核心能力：
- 理解自然语言
- 生成流畅文本
- 遵循指令完成任务

**本项目使用模型：Qwen2.5-1.5B-Instruct**

|------|------|

#### 2.4.2 什么是LoRA微调？

**LoRA**（Low-Rank Adaptation，低秩适配）是一种高效的大模型微调方法，由微软在2021年提出。

**核心思想：** 冻结预训练模型权重，在模型中插入可训练的低秩分解矩阵，只训练这些小矩阵。

#### 2.4.3 传统微调 vs LoRA微调

**传统微调（全参数微调）**

```
┌─────────────────────────────────────────────────────────────┐
│                    传统微调过程                              │
└─────────────────────────────────────────────────────────────┘

原始模型权重：W（15亿参数）
      ↓
微调时：更新所有15亿参数
      ↓
问题：
├─ 显存占用大（需要几十GB）
├─ 训练速度慢
├─ 存储成本高（每个任务存一份完整模型）
└─ 容易过拟合（数据量不足时）
```

**LoRA微调（低秩适配）**

```
┌─────────────────────────────────────────────────────────────┐
│                    LoRA微调过程                              │
└─────────────────────────────────────────────────────────────┘

原始模型权重：W（15亿参数）→ 冻结，不更新
      ↓
新增小矩阵：A × B（仅几百万参数）
      ↓
微调时：只更新A和B
      ↓
优势：
├─ 显存占用小（只需几GB）
├─ 训练速度快
├─ 存储成本低（只存小矩阵）
└─ 不易过拟合（参数少）
```

#### 2.4.4 LoRA核心原理详解

**1. 低秩分解数学原理**

```
┌─────────────────────────────────────────────────────────────┐
│                    低秩分解原理                              │
└─────────────────────────────────────────────────────────────┘

假设：模型权重的更新量 ΔW 是"低秩"的
即：ΔW 可以分解为两个小矩阵的乘积

数学表示：
ΔW = B × A

其中：
├─ W：原始权重矩阵，大小 d × d（如 4096 × 4096）
├─ A：降维矩阵，大小 d × r（如 4096 × 16）
├─ B：升维矩阵，大小 r × d（如 16 × 4096）
└─ r：秩（rank），远小于 d

参数量对比：
├─ 原始更新：d × d = 16,777,216 参数
├─ LoRA更新：d × r + r × d = 131,072 参数
└─ 压缩比：128倍！
```

**2. 前向传播过程**

```
┌─────────────────────────────────────────────────────────────┐
│                    LoRA前向传播                              │
└─────────────────────────────────────────────────────────────┘

输入向量 x
      ↓
┌─────────────────────────────────────────┐
│            原始路径                      │
│    y₁ = W × x                            │
│    （冻结权重，不参与训练）               │
└─────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────┐
│            LoRA路径                      │
│    h = A × x      （降维：d → r）        │
│    h = dropout(h) （防止过拟合）         │
│    y₂ = B × h     （升维：r → d）        │
│    y₂ = α/r × y₂  （缩放因子）           │
└─────────────────────────────────────────┘
      ↓
┌─────────────────────────────────────────┐
│            输出合并                      │
│    y = y₁ + y₂                           │
│    = W × x + (α/r) × B × A × x           │
└─────────────────────────────────────────┘

训练时：
├─ W 保持不变（冻结）
├─ A 和 B 参与训练
└─ 梯度只流向 A 和 B
```

**3. 为什么低秩分解有效？**

```
┌─────────────────────────────────────────────────────────────┐
│                    低秩假设的合理性                          │
└─────────────────────────────────────────────────────────────┘

理论依据：
├─ 预训练模型已经学到了通用的语言知识
├─ 微调只需要"调整"而非"重学"
├─ 权重更新量 ΔW 的"信息量"远小于原始权重 W
└─ 因此 ΔW 可以用低秩矩阵近似

实验验证：
├─ 秩 r=4~16 就能达到接近全参数微调的效果
├─ 更大的 r 收益递减
└─ 说明微调确实只需要调整少量参数
```

#### 2.4.5 LoRA关键参数详解

| 参数 | 代码配置 | 含义 | 影响 |
|------|---------|------|------|
| **r（秩）** | 16 | 低秩矩阵的维度 | 越大表达能力越强，但参数越多 |
| **lora_alpha** | 32 | 缩放因子 | 控制LoRA的影响强度，通常设为2×r |
| **lora_dropout** | 0.05 | Dropout比例 | 防止过拟合，提高泛化能力 |
| **target_modules** | all-linear | 应用LoRA的层 | 决定哪些层参与微调 |

**参数选择原则：**

```
秩（r）的选择：
├─ r=4~8：简单任务，数据量小
├─ r=16~32：中等复杂度任务（本项目选择）
└─ r=64+：复杂任务，数据量大

alpha的选择：
├─ 通常设为 2×r 或 r
├─ alpha/r 决定了LoRA的实际缩放比例
└─ 本项目：32/16 = 2.0

dropout的选择：
├─ 0.05~0.1：常用范围
├─ 数据量大时可减小
└─ 防止LoRA层过拟合
```

#### 2.4.6 目标模块选择

```
┌─────────────────────────────────────────────────────────────┐
│                    target_modules选择                        │
└─────────────────────────────────────────────────────────────┘

本项目配置：target_modules="all-linear"

含义：对所有线性层应用LoRA
├─ Q、K、V 投影层（注意力机制）
├─ Output 投影层（注意力输出）
├─ MLP 层（前馈神经网络）
└─ 其他所有 Linear 层

为什么选择 all-linear？
├─ 最大化微调效果
├─ 不需要手动选择层
└─ 对于1.5B小模型，显存足够

其他常见选择：
├─ ["q_proj", "v_proj"]：只微调注意力的Q、V层
├─ ["q_proj", "k_proj", "v_proj", "o_proj"]：微调所有注意力层
└─ ["q_proj", "v_proj", "gate_proj", "up_proj", "down_proj"]：注意力+MLP
```

#### 2.4.7 4-bit量化训练

```
┌─────────────────────────────────────────────────────────────┐
│                    4-bit量化原理                             │
└─────────────────────────────────────────────────────────────┘

为什么需要量化？
├─ 15亿参数的FP16模型需要约3GB显存
├─ 加上梯度和优化器状态，需要20GB+
├─ 普通显卡（8-12GB）无法承受
└─ 量化可以大幅降低显存需求

4-bit量化配置（QLoRA）：
├─ load_in_4bit=True：启用4-bit量化
├─ bnb_4bit_quant_type="nf4"：正态浮点量化
├─ bnb_4bit_use_double_quant=True：双重量化
└─ bnb_4bit_compute_dtype=float16：计算时使用FP16

NF4量化原理：
├─ NormalFloat4：专门为正态分布权重设计
├─ 权重通常服从正态分布
├─ NF4在正态分布区间内均匀分配量化点
└─ 比普通4-bit量化精度更高

双重量化：
├─ 对量化常数再量化
├─ 进一步压缩显存
└─ 几乎不损失精度

效果：
├─ 模型显存：约1GB（原需3GB）
├─ 可在8GB显卡上训练
└─ 精度损失可忽略
```

#### 2.4.8 训练过程详解

```
┌─────────────────────────────────────────────────────────────┐
│                    完整训练流程                              │
└─────────────────────────────────────────────────────────────┘

【第一步：数据准备】
原始数据 → 清洗过滤 → 构建Prompt → Tokenize
      ↓
过滤规则：
├─ 回复长度：50-600字
├─ 去除低质量回复（"正在研究"等）
├─ 去除负面核查回复（"未发现问题"等）
└─ 去重

【第二步：模型加载】
加载Qwen基础模型 → 4-bit量化 → 准备LoRA配置
      ↓
可训练参数：约400万（仅为原模型的0.3%）

【第三步：训练循环】
for epoch in range(3):
    for batch in dataloader:
        # 前向传播
        logits = model(input_ids)
        
        # 计算损失（只计算回复部分的loss）
        loss = cross_entropy(logits, labels)
        
        # 反向传播（只更新LoRA参数）
        loss.backward()
        
        # 梯度累积32步后更新
        optimizer.step()
        scheduler.step()

【第四步：保存模型】
保存LoRA权重（adapter_model.bin）
保存Tokenizer配置
```

**训练超参数配置：**

| 参数 | 值 | 说明 |
|------|-----|------|
| batch_size | 1 | 单卡batch大小 |
| gradient_accumulation | 32 | 梯度累积步数 |
| 有效batch_size | 32 | 1×32=32 |
| epochs | 3 | 训练轮数 |
| learning_rate | 5e-5 | 学习率 |
| max_length | 1024 | 最大序列长度 |
| optimizer | adamw_bnb_8bit | 8-bit AdamW |
| lr_scheduler | cosine | 余弦退火 |
| warmup_ratio | 0.05 | 预热比例 |

├─ 原始模型：精装大词典（占地方）

### 2.6 Flask Web框架

**核心作用：** 提供Web服务，连接前端和后端AI模块

**处理流程：**

```
前端请求 → Flask接收 → 调用AI模块 → 返回结果
```

**Flask是什么？**

Flask是一个Python Web框架，核心功能：
- 接收HTTP请求
- 路由分发（根据URL找到对应处理函数）
- 返回HTTP响应

**在本项目中的应用：**

| 接口 | 功能 |
|------|------|
| `/` | 返回主页HTML |
| `/api/analyze` | 分析留言，返回预测结果 |
| `/api/feedback` | 收集用户反馈 |
| `/api/health` | 检查服务状态 |

**Flask与HTML的关系：**
- HTML：定义网页结构（前端）
- Flask：处理业务逻辑（后端）
- Flask可以生成HTML返回给浏览器

### 2.7 模型缓存模块

**核心作用：** 避免重复加载模型，提升响应速度

**处理流程：**

```
第一次请求 → 加载模型到内存 → 缓存模型实例
后续请求 → 直接使用缓存的模型 → 快速响应
```

**为什么需要缓存？**
- 模型加载耗时：首次加载需要几秒到几十秒
- 内存占用大：模型占用几GB内存
- 解决方案：加载一次，多次使用

---

### 2.8 反馈存储模块

**核心作用：** 存储用户反馈，用于后续分析和改进

**处理流程：**

```
用户点击反馈按钮 → 收集反馈信息 → 存入SQLite数据库
```

**存储什么信息？**
- 留言内容
- 生成的回复
- 用户评价（有用/无用）
- 时间戳
