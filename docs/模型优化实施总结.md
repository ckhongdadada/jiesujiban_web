## 二、RAG检索模型优化

### 优化内容

#### 1. FAISS向量索引

**实现方式**：
- 当文档数量≥100时，自动构建FAISS IVF索引
- 小规模数据使用Flat索引
- 支持GPU加速（如果可用）

**预期效果**：
- 检索速度提升10-100倍
- 支持更大规模的文档库
- 内存占用更可控

**使用方法**：
```python
from enhancements.rag_retriever_bge_optimized import PolicyRetriever

retriever = PolicyRetriever(
    corpus_path="path/to/corpus.jsonl",
    backend="bge",
    enable_cache=True
)

# 检查是否启用了FAISS
print(retriever.describe())
```

#### 2. 查询缓存

**实现方式**：
- 基于查询参数（query、district、tag、unit、top_k）生成缓存键
- LRU淘汰策略，默认缓存1000条
- 线程安全设计

**预期效果**：
- 重复查询速度提升90%以上
- 减少模型推理次数
- 降低系统负载

**使用方法**：
```python
# 自动缓存
results = retriever.search(query="垃圾清运", top_k=3)

# 查看缓存统计
stats = retriever.get_cache_stats()
print(f"命中率: {stats['hit_rate']:.2%}")

# 清空缓存
retriever.clear_cache()
```

#### 3. 批量检索

**实现方式**：
- 向量化批量编码查询
- 批量计算相似度
- 批量处理结果

**预期效果**：
- 吞吐量提升5-10倍
- GPU利用率提升
- 适合高并发场景

**使用方法**：
```python
queries = ["垃圾清运问题", "噪声扰民", "停车秩序"]
districts = ["朝阳区", "海淀区", "丰台区"]

# 普通批量检索
results = retriever.batch_search(queries, top_k=3, districts=districts)

# 优化的批量检索（向量化）
results = retriever.batch_search_optimized(queries, top_k=3, districts=districts)
```

## 三、生成模型优化

### 优化内容

#### 1. KV Cache优化

**实现方式**：
- 缓存已计算的KV Cache
- 检测Prompt前缀匹配，复用缓存
- LRU淘汰策略，默认缓存10条

**预期效果**：
- 生成速度提升2-3倍（对于相似Prompt）
- 减少重复计算
- 降低GPU内存峰值

**使用方法**：
```python
from enhancements.enhanced_generation_optimized import (
    generate_reply_with_context,
    get_generation_stats
)

# 自动使用KV Cache
result = generate_reply_with_context(
    tag="市容环卫",
    title="垃圾清运问题",
    body="...",
    unit="街道办事处",
    location_result={},
    retrieval_hits=[],
    use_cache=True  # 启用缓存
)

# 查看KV Cache统计
stats = get_generation_stats()
print(stats['kv_cache_stats'])
```

#### 2. 批量生成

**实现方式**：
- 批量构建Prompt
- 批量编码和生成
- 动态批次大小调整

**预期效果**：
- 吞吐量提升5-10倍
- GPU利用率从20-30%提升到80-90%
- 适合批量处理场景

**使用方法**：
```python
from enhancements.enhanced_generation_optimized import batch_generate

requests = [
    {
        "tag": "市容环卫",
        "title": "垃圾清运问题",
        "body": "...",
        "unit": "街道办事处",
        "location_result": {},
        "retrieval_hits": []
    },
    # ... 更多请求

```

#### 3. 流式输出

**实现方式**：
- 使用TextIteratorStreamer
- 多线程生成
- 实时输出文本块

**预期效果**：
- 首字延迟降低到100-200ms
- 用户体验显著提升
- 适合交互式场景

**使用方法**：
```python

for chunk in generate_stream(
    tag="市容环卫",
    title="垃圾清运问题",
    body="...",
    unit="街道办事处"

    print(chunk, end="", flush=True)
```

#### 4. 模型预热

**实现方式**：
- 加载后自动执行3次预热推理
- 初始化CUDA Kernel
- 分配内存

**预期效果**：
- 首次请求延迟从500-1000ms降低到50-100ms
- 避免用户首次请求超时

## 四、地名识别模型优化

### 优化内容

#### 1. 结果缓存

**实现方式**：
- 基于文本内容生成缓存键
- LRU淘汰策略，默认缓存5000条
- 线程安全设计

**预期效果**：
- 重复识别速度提升95%以上
- 减少API调用次数
- 降低系统负载

**使用方法**：
```python
from enhancements.location_ner_optimized import BeijingDistrictResolverOptimized

    enable_cache=True,
    cache_size=5000
)

```

#### 2. API限流

**实现方式**：
- 令牌桶算法
- 默认10次/秒
- 自动等待和重试

**预期效果**：
- 避免API配额耗尽
- 控制调用频率
- 提供调用统计

**使用方法**：
```python

    amap_api_key="your_api_key",
    amap_rate_limit=10.0  # 10次/秒
)

# 自动限流
result = resolver.resolve("某地址")

# 查看API调用统计

```

#### 3. Trie树匹配

**实现方式**：
- 构建地名Trie树
- O(n)时间复杂度匹配
- 支持最长匹配

**预期效果**：
- 匹配速度提升10倍以上
- 支持大规模别名库
- 更准确的匹配结果

**使用方法**：
```python

# 自动使用Trie树匹配

```

#### 4. 批量识别

**实现方式**：
- 批量处理文本

**预期效果**：

**使用方法**：

## 八、注意事项

### 1. 内存管理

- FAISS索引会占用额外内存，建议至少预留文档向量大小的2倍内存
- KV Cache会占用GPU内存，建议根据显存大小调整缓存数量
- 统一缓存默认10000条，可根据实际情况调整

### 2. 并发安全

- 所有缓存操作都是线程安全的
- 模型加载使用锁保护，避免重复加载
- 建议使用单例模式管理模型实例

### 3. 缓存策略

- 默认使用LRU淘汰策略
- 支持TTL过期（统一缓存）
- 建议定期清理过期缓存

### 4. 性能监控

- 使用`@monitor_performance`装饰器监控关键函数
- 定期查看缓存统计信息
- 根据统计数据调整缓存大小
